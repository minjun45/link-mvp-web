## Figma V4.1 디자인 반영

개발 A·B 구분에 앞서 적용한 변경이다. 커밋 `25d3c6b`.

- **공통 화면**에 Pretendard Variable을 적용하고 제목·본문·버튼의 스타일을 정리했다. 화면을 스크롤하면 상단에 짧은 제목을 표시하고, 아래에 내용이 더 있으면 스크롤 안내를 표시한다.
- **메뉴·장바구니**에서 메뉴를 분류별로 구분하고 품절 사유를 표시한다. 음료와 기타 상품의 수량 단위를 ‘잔’과 ‘개’로 구분했다. 메뉴를 담은 뒤에는 확인창에서 ‘장바구니로 이동’과 ‘메뉴 더 고르기’를 선택할 수 있다.
- **설정·결제**에서는 ‘직원에게 보여주기’ 설정으로 하단 직원 도움 버튼을 켤 수 있게 했다. 결제가 취소 또는 실패로 확정되면 담은 메뉴를 유지한 채 다시 결제할 수 있다.

## 개발 A파트 공통 초점

아래 표는 #9 당시의 기록이다. #8 통합 후에는 주문 화면 전환 시 새 제목을 한 번 읽도록 초점을 옮긴다. 결제 실패 시에는 ‘결제에 실패했어요’, 주문 현황에서 준비 완료로 바뀌면 자동으로 픽업 화면에 들어가 ‘음료가 준비됐어요’ 제목에 초점이 간다. 데모 매장 검색은 8초 예고와 결과 안내를 유지한다.

### 데모 검색과 실제 매장 검색

8초 대기는 데모에만 적용한다. 시작 문구는 화면과 스크린 리더용 상태 영역에 동일하게 제공한다.

> 데모에서는 8초 후 매장 검색 결과가 자동으로 표시돼요.

검색 결과가 여러 곳이면 실제 개수와 다음 행동을 알린다. 예를 들어 “데모 매장 3곳을 찾았어요. 매장을 선택해 주세요.”라고 안내한다. 한 곳이면 매장 이름을 알리고 상세로 이동하며, 0곳이면 찾지 못했다는 결과를 알린다. 검색을 중단하면 대기 중인 결과 전환도 취소된다.

## 검증 결과와 실기기 확인 사항

최종 코드 `ea6278e`에서 자동 테스트 **72개**와 프로덕션 빌드가 통과했다. Chrome에서 데모 검색부터 주문 준비 완료·픽업까지 확인했다. A-3 반영 당시에는 테스트 데이터로 41개 화면의 44개 상태를 검사했고, 접근성 트리에 노출된 컨트롤 261건 중 이름이 빈 항목은 없었다.

| **A-4 · iPhone VoiceOver 홈 탐색** | 같은 빌드에서 Safari 직접 접속과 QA 캡처에 나타난 Menlo 경유 접속을 비교한다. 오른쪽으로 쓸어넘길 때 불필요한 ‘이미지’가 반복되는지, ‘실제 매장 찾기’와 ‘데모 매장으로 진행하기’에 각각 도달해 이중 탭으로 실행할 수 있는지 기록한다. |

다음 개별 검토 대상은 개발 A파트 ‘진입 화면’의 **Galaxy TalkBack에서 ‘데모 매장으로 진행하기’에 초점이 가지 않는 문제**다. 같은 절의 ‘찾은 매장 수 음성 안내’와 ‘매장 상세 정보 항목에 제목 제공’은 각각 A-6과 A-5에 관련 구현이 있으므로 해당 빌드로 확인한다.

## 후속 수정과 재검증

결제를 승인한 뒤 새로고침해도 기존 주문번호와 금액으로 현황을 복구하고, 최신 준비 상태를 조회한다. 미확정 결제는 주문보다 우선한다. 결제 확인과 결제 완료 화면에서 사용할 수 없는 ‘뒤로’ 버튼을 제거했다. 오래된 저장 데이터를 읽을 때 유효한 장바구니 줄과 매장별 이력을 보존하며, 읽을 수 없는 결제·주문 기록은 새 요청을 막고 기존 결제 확인을 안내한다.

음성 검색을 시작한 버튼에서 취소할 수 있다. 메뉴 더 보기는 실제 추가 개수를 버튼에 표시하고, 목록을 펼친 뒤 새 항목으로 초점을 옮긴다. 직원 도움 카드의 내용은 스크린 리더로 탐색할 수 있다. 장바구니 수량 단위는 상품별로 표시한다.

- **VoiceOver / TalkBack** — 홈에서 실제 매장과 데모 버튼까지 순차 탐색한다. 매장 상세 제목·값을 확인하고, 음성 검색 시작·취소·같은 검색어 재실행에서 결과 제목이 한 번 읽히는지 확인한다.
- **SenseReader / 키보드** — Tab·Shift+Tab·Enter·Space·Escape로 검색, 메뉴 더 보기, 옵션, 장바구니와 직원 도움 카드를 실행한다. 카드 제목에 초점이 들어가고, 닫으면 열었던 버튼으로 돌아오는지 확인한다.
- **작은 화면과 확대** — 200% 확대, 큰 글씨, 고대비에서 본문과 고정 하단 영역을 스크롤한다. 품절·빈 장바구니·결제 로딩·오류 안내가 잘리지 않고 각 화면에서 사용할 수 있는 버튼에 도달하는지 확인한다.
- **데모 결제 복구** — 테스트 결제 직후, 준비 중, 준비 완료 후 각각 새로고침해 주문번호와 금액이 동일한지 확인한다. 미확정 상태에서는 기존 결제 확인 경로가 유지되고, 픽업 완료 후에는 주문이 자동으로 다시 열리지 않아야 한다.

실기기 스크린 리더 항목은 후속 확인 대상이다. 결제 실패·응답 유실·중복과 저장 복구는 로컬 모의 결제 및 가짜 서버 응답으로 검증한다.

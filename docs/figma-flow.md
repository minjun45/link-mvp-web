# Figma 흐름 대응

## 현재 진입 흐름 · 1103 설계 반영 (2026-11-09)

`V5-01`부터 `V5-05` 직전까지의 기준은 프로젝트 루트의 **`매장 주문·결제 화면 설계_1103.fig`**, `08 1103 V4 · 초안 3-1` 페이지다. 이 구간은 아래 표를 우선한다. 메뉴 선택 이후의 구현은 이번 수정 범위에 포함하지 않았다.

후속 요청으로 진입 전에 **START 선택 화면**을 추가했다. 첫 실행/재방문 모두 `START → 실제 매장 찾기 또는 데모 매장으로 진행하기 → V5-01` 순서다. 실제 선택은 버튼 클릭과 동시에 Bluetooth 요청을 시작하고, 데모 선택은 Bluetooth 없이 약 2초 후 후보 목록을 표시한다. 사용법은 설정에서 따로 열며 종료 후 START로 돌아간다. 픽업 완료 후에도 START에서 다시 선택한다. 저장된 미확정 결제가 있으면 선택 화면보다 결제 복구를 우선한다.

흐름은 `01 → 02 → 03 → 04 → 05`, 미탐색은 `01 → 01e`, 목록에 원하는 매장이 없으면 `02 → 02e → 02s → 03`이다. 검색 결과와 선택은 뒤로 가기에서 복원하고, 자동 로딩 화면은 뒤로 가기 기록에 추가하지 않는다. 화면을 떠나면 탐색 타이머와 늦은 응답을 무시한다. 매장 변경으로 기존 장바구니를 비우는 경우에는 기존 확인 절차를 유지한다.

진입 화면은 390px 와이어프레임 폭, 회색 배경·흰 카드, 본문 여백 24px·간격 16px, 노란 주 버튼, 하단 보조 버튼과 직원 도움 배치를 사용한다. 작은 화면/큰 글씨에서는 스크롤로 모든 행동에 접근할 수 있다. OS 상태 표시줄은 웹에서 그리지 않는다.

### 웹 환경에서 달라지는 부분

- Bluetooth는 START의 실제 매장 찾기 또는 다시 찾기 클릭 핸들러에서 즉시 요청한다. 01 본문에는 별도의 검색 버튼을 두지 않는다. 브라우저의 기기 선택 창은 계속 사용하며, 사용자 입력 없는 백그라운드 스캔을 구현한 것은 아니다. 지원하지 않는 브라우저에서는 01e의 이름 검색을 이용할 수 있다. 실물 비콘 성공 여부는 별도 검증이 필요하다.
- 실측 위치·거리·RSSI가 없으므로 ‘가장 가까운’, 예시 거리·위치 기준이라는 표현은 사용하지 않는다. 검색 대상은 API/카탈로그의 참여 매장이다.
- 대기 정보는 `Store.wait = { ordersAhead, minutes }`가 제공될 때 표시하고, 없으면 ‘매장에서 확인해 주세요’를 표시한다. 예시 대기 시간을 실측값으로 표시하지 않는다.
- 데모 선택은 START에 배치했다. 설정에서는 **매장 찾기 방식 선택**으로 START를 다시 열 수 있다. 데모는 로컬 테스트 모드로 진행하며 서버 모드에서 전환할 때에는 기존 연결 변경과 같은 장바구니·최근 주문 초기화 규칙을 적용한다. 진행 중 결제가 있을 때에는 먼저 결제 결과를 확인한다.

## 이전 구현 기준 기록 · 09 프로토타입

아래는 기존 Android 재사용 버전의 기록이다. **진입 화면 ID와 흐름은 위의 1103 표로 대체되었다.** 아래 09 페이지는 `_1103.fig`에 포함되지 않은 다른 파일의 페이지다.

기준 파일: `테크포임팩트 5팀 링크 — 매장 주문·결제 화면 설계.fig` (이 작업 공간의 로컬 파일). 09 페이지의 실제 interaction 대상과 08 페이지의 명시된 보완안을 읽어 적용했습니다. 이전 PDF/이전 페이지의 충돌하는 중간 화면보다 최신 08/09를 우선합니다.

## 프로토타입과 실행 앱의 차이

- Figma의 1.5/2.5/4초 interaction 타이머는 데모 전환입니다. 앱은 실제 BLE 결과·API 응답·서버 주문 상태를 기다립니다. 기기 내 데모 상태만 접수 8초/준비 25초로 시뮬레이션합니다.
- 데모 매장 탐색으로 시작한 주문은 픽업 완료 후 12→O1로 돌아갑니다. 일반 주문은 새 매장 탐색으로 이동합니다. 사용법 완료 기록과 이전 주문은 보존합니다.
- 메뉴나 옵션에서 뒤로 가면 직전 화면과 선택을 복원합니다. 자동 메뉴 로딩 화면은 건너뛰며 장바구니와 결제 상태는 유지합니다. 최근 메뉴는 지난 옵션이 채워진 V5-06에서 다시 확인합니다.
- RSSI는 매장 정렬에만 사용하며 실제 거리(미터)로 꾸며 표시하지 않습니다. 실물 비콘 광고 이름이 카탈로그의 `beaconName`과 일치해야 합니다.
- 실물 비콘이 없을 때 사용자가 명시적으로 선택하는 데모 탐색, 테스트 결제 결과 버튼, 개발 서버 설정은 실행·검증을 위한 추가 경로입니다.
- 기기 내/서버 데모는 POS·실매장 전송·제조 완료 푸시를 구현한 것으로 표시하지 않습니다. Kakao 테스트 서버 연동 코드는 포함하지만 키·실기기 전환 검증은 별도입니다.
- `09`의 390px 프레임에서 본문 여백 24px, 요소 간격 16px, 주요 버튼 높이 72px, 보조 도움 버튼 높이 60px를 가져왔습니다. 앱에서는 같은 수치를 dp 기준 최소 크기로 적용합니다.
- 원본에서 추출한 벡터 아이콘을 사용합니다. Android에는 Noto Sans KR을 포함했고 메뉴 사진 영역은 원본 와이어프레임의 자리 표시를 따릅니다. 원본 예시의 가격·거리·대기 시간은 앱 데이터와 탐색 결과에 따라 달라집니다.
- 상태 표시줄은 Android 시스템이 그립니다. 좁은 화면이나 큰 글씨 설정에서는 보조 버튼이 스크롤 영역에 배치됩니다. 실기기 캡처를 Figma와 겹쳐 보는 검증은 별도로 필요합니다.
